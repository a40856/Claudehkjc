# Plan — pre/post-race odds + dashboard rebuild

## Scope (user-confirmed)

1. **Option B**: store BOTH pre-race live odds (WIN / PLA / QIN / QPL) AND post-race final dividends (WIN / PLA / QIN / QPL / FOR / TRIO / F4 / Quartet).
2. **Redesign `docs/index.html`** as a proper dashboard, adding features incrementally.
3. **Click-on-horse** → opens a side panel with horse history (existing data we already have in `data/horses.csv`).
4. **Cross-check table** comparing our model's top-4 vs actual finishing order, with all odds/dividends inline.
5. **Accuracy dashboard** per-meeting + cumulative.
6. **Review & improvement workflow**:
   - Identify which weights/factors led to wrong picks
   - Identify which picks nailed it and why
   - Adjust weights based on evidence

## What's hard

1. **HKJC QQP page renders odds client-side via JS** — raw HTML scrape sees empty cells. The JSON endpoint `/racing/getJSON.aspx?...` is the reliable path for pre-race odds (already used by `live_odds.py` but only partially — need to also fetch QIN/QPL not just WIN).
2. **Dividends** come from the results page after race ends (zhhk/localresults). Different URL than pre-race.
3. **Value-bet detection** needs both numbers side-by-side: `model.calc_odds` vs `market.win_odds` vs `final.win_dividend`.

## What I'll build (in order)

### Phase 1 — Data pipeline (server-side, no UI yet)

| File | What |
|---|---|
| `live_odds.py` (rewrite) | Fetch pre-race WIN/PLA/QIN/QPL via JSON endpoint for any race date+venue, save to `data/odds/YYYY-MM-DD_VN_pre.json` |
| `scripts/fetch_dividends.py` (NEW) | Fetch post-race dividends from results page, save to `data/odds/YYYY-MM-DD_VN_post.json` |
| `scripts/merge_odds.py` (NEW) | Merge pre + post into a single per-race `data/odds/YYYY-MM-DD_VN_odds.json` (machine-friendly, used by dashboard) |
| `scripts/model_accuracy_report.py` (extend) | Add columns: `win_odds_pre`, `place_odds_pre`, `qin_odds_pre`, `win_div`, `place_div`, `qin_div`, `qpl_div`. Add **value-bet flags**: `value_overlay_win`, `value_overlay_place` (= model_says_X / market_says_Y ratio) |
| New GitHub Action `weekly-audit.yml` step | After review, call `fetch_dividends.py` for the reviewed meeting |

### Phase 2 — Dashboard (rewrite `docs/index.html`)

Single dark-themed page served via GitHub Pages. No build step (vanilla JS + inline CSS).

**Top section — meeting picker**
- Dropdown of all available meetings (last 24)
- Date range filter
- Venue filter (ST / HV)

**Per-meeting view**
- Header: meeting date, venue, race count, accuracy summary
- Cross-check table: for each race, show top-4 picks vs actual top-4, with pre-race odds, post-race dividend, hit/miss badge, **value-bet indicator**
- Click horse name → slide-out panel with that horse's lifetime stats (from `horses.csv`) + last-6 form graph (sparkline)

**Accuracy dashboard tab**
- Cumulative win rate / place rate / top-4 rate over time (line chart)
- Per-meeting accuracy bar chart
- P1 hit rate trend
- Best/worst meetings highlight
- **Below-average meeting flags** (auto-mark meetings where top-4% is >1 std dev below mean)

**Improvement analysis tab**
- Show weight file's current values
- "If we had used these alternative weights" toggle — re-score the last 11 meetings live in browser, show diff in hit rate
- Per-meeting deep-dive: for each "miss" (P1 didn't hit top-4), show which 3 factors contributed most positively vs negatively

### Phase 3 — Review workflow integration

A `scripts/analyze_misses.py` script:
- For every meeting, find horses that were top-3 in model but finished 5th+
- For each miss, compute feature contributions (which score pushed it up)
- Output a markdown report per meeting → `reports/misses/YYYY-MM-DD_VN.md`
